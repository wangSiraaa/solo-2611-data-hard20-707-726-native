# 定高页对账输入

`entries.json` 是初始修订。`operations.jsonl` 依次请求初始发布、原子更正、发布新切面和复读旧报告。全为合成整数，格式中的 `cut` 指该次请求所用源切面，后端和发布器需要实现。

页高为 7，组头和本页的接续提示或末页小计各高 1，所以明细最多占 5。初始六项行高 `[1,1,1,1,1,2]`。逐页贪心填到五项会留下单条尾页，两页切成 4+2 或 3+3 都合法。总金额 60，4+2 的第二页前累计 40。

更正前四项的行高为 2，并把首项金额改为 11。新行高 `[2,2,2,2,1,2]`，总明细高度 11，至少需三页。2+2+2 合法，页前累计依次为 0、21、41，末页小计 61。新切面若用页高 5，明细每页最多高 3，首两项合计高 4，又不许单项成页，因此应拒绝。
